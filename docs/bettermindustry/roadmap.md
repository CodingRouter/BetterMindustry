# 短期路线图

路线按可验证的工程结果排列，不先承诺发布日期。每一阶段通过退出条件后，才扩大范围。

## M0：固定上游基线（已完成）

交付：

- 克隆 Mindustry `v160.7`，建立 `main` 稳定主干。
- 固定提交、许可证、JDK 和构建命令。
- 跑通已有测试、服务端构建和桌面端构建。
- 建立 BetterMindustry 的项目文档与平台代码目录。

退出条件：

- [x] `.\gradlew.bat tests:test` 通过。
- [x] `.\gradlew.bat server:dist` 通过。
- [x] 产物可以在本机以原版配置启动。
- [x] `.\gradlew.bat desktop:dist` 通过。

## M1：双世界进程技术原型

交付：

- 控制层用 `ProcessBuilder` 启动和停止世界进程。
- 每个世界拥有独立端口、配置、存档和日志目录。
- 支持列出世界、查看健康状态、优雅停机。
- 同一台机器同时运行两个世界，原版客户端可以分别连接。

退出条件：

- 两个世界连续运行至少 10 分钟。
- 杀死其中一个进程后，另一个世界仍能继续服务。
- 重启控制层后，两个世界能从各自存档恢复。

这是第一个真正的产品里程碑；它证明“多世界平台”不是只在图上的概念。

### M1A：精确 Sector Worker（进程级验收通过）

- 每个 Sector 使用完整固定 Tick，无玩家时只关闭渲染、音频和高频网络广播。
- 建立 `SectorId`、运行状态、权威租约、游戏时钟和检查点元数据。
- 验证两个 World Worker 在一段时间内持续推进且不会相互影响。
- 10 分钟连续运行、强制终止隔离和控制层恢复均已通过。

### M1B：多视口客户端

- Gateway 按 `sectorId` 多路复用世界订阅。
- 客户端维护多个 `WorldView`，主线程顺序绑定后处理网络包和渲染。
- 第一版验证两个独立视口，不要求无缝跨地图边界。
- 玩家控制权只属于一个 Focus Sector，其他视口为观察模式。

当前进展：Gateway、浏览器多 WorldView、输入幂等、账户与角色授权已完成；真正的
Mindustry 桌面多视口客户端、移动/建造输入和登录限流尚未实现。

## M2：控制层与持久化

交付：

- 世界清单与生命周期状态机：创建、启动、运行、停止、失败、恢复。
- 端口和实例资源分配。
- 管理 API 或本地 CLI，记录结构化审计日志。
- 世界元数据：名称、地图、版本、种子、玩家、状态和最近检查点。

退出条件：

- 管理操作可以重复执行且结果可预测。
- 控制层意外重启后能重建当前拓扑。
- 单个世界崩溃会被明确报告，不会被静默重启覆盖证据。

## M3：多世界客户端入口

交付：

- 客户端显示世界列表、人口、状态和版本。
- 玩家选择世界后接入对应世界进程。
- 第一阶段允许“断开并切换世界”，暂不承诺无缝跨图。
- 服务端通过能力协商告知客户端是否支持扩展功能。

退出条件：

- 原版世界仍可由原版客户端连接。
- BetterMindustry 客户端能区分原版世界和扩展世界。
- 不混用不兼容的协议版本。

## M4：跨世界玩法与持续模拟

交付：

- 跨世界事件协议：传送、资源转运、战役消息和全局任务。
- 离线世界的固定 Tick 追赶与检查点。
- 生产账本，记录实际产出、输入不足、堵塞、电力不足和模拟跳变。
- 可复现实验：相同存档、种子和 Tick 数得到相同结果。

退出条件：

- 跨世界操作是服务端权威、可审计和可限流的。
- 离线模拟不会悄悄跳过 Tick 却仍标记为“精确”。
- 性能测试给出固定硬件下的模拟倍率和世界数量上限。

## M5：战役与视觉表现

交付：

- 队伍、星区和长期战役玩法。
- 二维动态光照、阴影、环境光遮蔽、Bloom 和可分级画质。
- 远距离世界使用摘要视图，避免客户端同时模拟多个地图。

先做性能预算再扩展视觉效果。任何画面选项都必须能关闭或降级。

## 暂不做

- 一开始就把单张地图切成随机线程并行模拟。
- 用多个变量的实时估算冒充精确离线产出。
- 在协议、存档和权威模型稳定前制作完整玩法内容。
- 为了视觉效果牺牲原版低配设备和手机可玩性。
