# ADR-0003：在线仓库从 Mindustry v160.7 源码快照独立起史

- 状态：已接受
- 日期：2026-10-22

## 背景

BetterMindustry 以 Mindustry v160.7 为起点，但计划重构多世界服务端、客户端渲染、联机协议和长期宇宙玩法。完整 Mindustry 历史约 1.9 GiB，而当前源码快照与 BetterMindustry 文档约 94 MiB。

完整历史适合持续跟随上游的场景，但本项目预期大幅分化。

## 决策

在线仓库使用独立根提交，保存 v160.7 的完整源码树、文档、许可证和上游提交号，但不携带 Mindustry 的 Git 祖先历史。

完整历史保存在本地分支：

```text
archive/mindustry-full-history
```

该归档分支不推送到公开仓库。

## 上游同步

后续 Mindustry 版本通过以下流程同步：

1. 从 `upstream` 获取目标提交。
2. 在独立工作区或归档历史中比较源码树。
3. 人工筛选 Bug 修复、安全更新和兼容性变化。
4. 形成独立提交并补充测试。
5. 记录来源版本和上游提交号。

不使用普通分支合并，避免重新引入完整上游历史。

## 后果

优点：

- 初始推送和克隆体积显著降低。
- GitHub Actions 和协作者首次拉取更快。
- BetterMindustry 主干只包含自己的开发历史。
- 上游源码、GPL 许可和来源仍然完整。

代价：

- 不能直接快进或自动合并 Mindustry 上游。
- `git bisect` 无法跨越上游历史自动定位问题。
- 需要维护人工上游同步流程。

在项目重新以跟随上游为主要目标之前，不撤销该决定。
