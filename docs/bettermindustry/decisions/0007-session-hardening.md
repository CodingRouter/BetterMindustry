# ADR-0007：Session 加固使用滑动窗口限流与可撤销设备列表

- 状态：已接受，第一阶段已实现
- 日期：2026-10-22

## 背景

账户角色已经建立，但连续猜密码没有限制，用户也无法查看或撤销其他设备。只靠 7 天 Cookie
无法满足长期服务器最基本的账号安全需求。

## 决策

### 登录限流

- 键为“远端地址 + 规范化用户名”。
- 窗口为 5 分钟。
- 第 5 次失败后拒绝后续登录。
- HTTP 429 携带 `Retry-After`。
- 成功登录清除对应失败记录。
- 内存最多跟踪 2,048 个组合。

### 设备 Session

- Session 保存清理后的 User-Agent 标签。
- 列表只返回 Client ID、账户、角色、标签和时间，不返回令牌或哈希。
- PLAYER 可以撤销自己的任意 Session，并退出其他设备。
- ADMIN 可以查看全部 Session 并强制撤销。
- 撤销后同步清除 Focus、ViewMode 和控制租约。

## 为什么暂不显示 IP

当前目标是把设备身份和撤销路径做正确。IP 属于更敏感的数据，需要脱敏、保留期限、审计和
隐私策略，不能因为底层能拿到就默认展示。

## 后果

优点：

- 基础密码爆破有明确退避。
- 用户能自行关闭丢失或不认识的设备。
- 管理员有强制处置入口。
- 管理接口不会暴露 Session 凭据。

代价：

- 限流状态只存在单个 Orchestrator 进程内。
- 多实例部署需要 Redis、数据库或独立安全服务提供共享限流。
- User-Agent 标签可以被客户端伪造，只用于识别，不作为安全凭据。
