# ADR-0001：第一阶段使用独立进程承载每个世界

- 状态：已接受
- 日期：2026-10-22

## 背景

目标平台需要同时运行多个地图，并让玩家跨地图联机。最直观的想法是在一个进程里为每张地图开一个线程，但 Mindustry 当前游戏生命周期包含大量全局状态。地图、网络、渲染和模拟之间没有天然的多世界隔离边界。

如果一开始就重构成跨区块多线程模拟，会同时处理全球状态、区块依赖、确定性、网络同步和存档迁移，风险过高。

## 决策

第一阶段一个世界对应一个独立 JVM 进程：

- 独立端口。
- 独立配置、存档、日志和检查点。
- 独立权威 Tick。
- 由控制层创建、路由、监控和停止。

一个世界内部保持确定的串行 Tick。辅助功能可以使用线程，但不能改变游戏状态提交顺序。

## 后果

优点：

- 世界崩溃互相隔离。
- 存档和升级可以逐世界进行。
- 无需先重写全部全球单例。
- 原型能快速验证多世界产品体验。

代价：

- 每个世界有固定 JVM 内存开销。
- 控制层需要处理端口、进程健康、重启和日志归属。
- 跨世界低延迟需要额外通信层。

## 重新评估条件

只有满足以下条件后才考虑同 JVM 多世界：

- 实测证明进程开销成为主要瓶颈。
- 已完成全球状态的实例化边界设计。
- 有确定性测试证明多世界不会互相干扰。
- 世界迁移和故障隔离不会被削弱。
