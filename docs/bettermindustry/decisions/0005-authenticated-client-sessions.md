# ADR-0005：认证 Client Session 由服务端签发

- 状态：已接受，第一阶段已实现
- 日期：2026-10-22

## 背景

早期原型使用浏览器 `localStorage` 保存 `Client ID` 并通过 `X-BM-Client-Id` 发送。任何
请求只要修改这个头就能冒充其他客户端，控制租约、输入审计和幂等回执的身份边界都不可信。

## 决策

Gateway 签发不透明访客 Session：

- Client ID 由服务端生成。
- 认证凭据是 256 位 `SecureRandom` 随机令牌。
- 浏览器只通过 HttpOnly、SameSite=Strict Cookie 持有令牌。
- 状态文件只保存令牌 SHA-256 哈希。
- Session 固定 7 天过期，最多保留 64 个。
- 除首页和 Session 端点外，所有控制和资源 API 都要求认证。
- 撤销 Session 时删除 Client Session，并释放它持有的全部控制租约。
- SSE 使用同源 Cookie，不把身份凭据放进查询参数。

本地控制面同时校验 Host 和不安全方法的 Origin，降低 DNS rebinding 与跨站请求风险。

## 为什么不是长期 JWT

第一阶段只需要服务端可立即撤销的本地会话。随机不透明令牌允许 Gateway 在任何时刻删除
哈希并立刻生效；在当前没有独立身份服务、密钥轮换和跨服务验证需求时，引入 JWT 只会增加
令牌吊销和密钥管理复杂度。

## 后果

优点：

- 客户端不能再自行声明身份。
- 状态文件泄露不会直接暴露可用令牌。
- Session 可跨 Orchestrator 重启恢复。
- 控制权生命周期与认证 Session 生命周期一致。

代价：

- 当前仍是自动签发的访客身份，不是正式用户账户。
- 还没有设备列表、踢出其他设备和多设备管理 UI。
- 令牌哈希使用当前状态文件的原子写入，未来规模扩大后应迁移到数据库。
