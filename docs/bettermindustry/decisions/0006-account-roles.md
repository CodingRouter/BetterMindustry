# ADR-0006：本地账户使用 PBKDF2 与三级角色

- 状态：已接受，第一阶段已实现
- 日期：2026-10-22

## 背景

认证 Session 解决“不能伪造 Client ID”，但访客身份本身没有权限差异。观察、控制 Sector
和启停 Worker 的风险不同，需要先建立最小角色边界。

## 决策

角色从低到高为：

```text
GUEST < PLAYER < ADMIN
```

- GUEST 可以查看状态和订阅画面。
- PLAYER 可以取得控制租约和发送受控输入。
- ADMIN 可以管理 Worker 生命周期和执行本地管理命令。

账户密码使用：

- `PBKDF2WithHmacSHA256`。
- 16 字节 `SecureRandom` 盐。
- 210,000 次迭代。
- 256 位派生哈希。
- 每账户独立盐和参数版本。

账户数据写入独立 `accounts.properties`，使用临时文件原子替换；文件系统不支持原子移动时
回退到同目录直接替换。Session 只保存账户名，认证时实时读取账户角色。

## 引导规则

当前控制面只监听 `127.0.0.1`，因此第一个注册账户自动成为 ADMIN，后续账户为 PLAYER。

这不是适合公网部署的引导方式。远程开放前必须改为：

- 安装时生成一次性管理员凭据。
- 或由本机管理员 CLI 创建首个账户。
- 并增加登录限流、密码重置和管理员撤销。

## 后果

优点：

- 不同风险操作有明确授权边界。
- 密码文件泄露不能直接得到明文密码。
- 角色变更后，现有 Session 在下次认证时读取新角色。
- 账户数据与 Gateway 会话/回执状态分离。

代价：

- 当前账户存储规模适合单机原型，不适合多实例并发写入。
- 尚未提供密码恢复、角色管理和登录限流。
- 首个账户自动 ADMIN 的规则只能用于本地受信环境。
