# ADR-0004：Game Tick 与 Render Tick 分离

- 状态：已接受，分阶段实现
- 日期：2026-10-22

## 背景

BetterMindustry 要求无玩家 Sector 持续精确模拟，同时客户端可能同时渲染多个 Sector。如果画面帧率、镜头移动和渲染卡顿参与权威模拟，就无法保证世界一致性和加速追赶。

## 决策

长期架构拆成两个时钟平面：

### Game Tick Plane

- 每个 Sector 一个权威 Actor/Worker。
- 固定模拟步长。
- 负责资源、单位、建筑、电力、波次和逻辑。
- 可以无渲染运行，也可以按固定 Tick 加速追赶。
- 输出带 `sectorId` 和 `tick` 的快照/增量。

### Render Tick Plane

- 使用现实帧率。
- 负责相机、插值、粒子、光照和 UI。
- 可以丢帧或降级。
- 不修改权威库存、位置和战斗结果。
- 通过订阅多个 Sector 的 Game Tick 输出实现多视口。

## 第一阶段

Web 调试器只运行和观察 Game Tick Worker。Render Tick 仅显示为计划节点，不创建虚假的渲染实现。

## 后续接口

Render Tick 接入前至少需要定义：

- 初始世界快照。
- Tile/建筑增量。
- 实体快照与插值数据。
- 订阅、取消订阅和 Sector 切换。
- 游戏 Tick 与渲染帧的时间基准。
- 背压、丢帧和降级策略。

## 后果

- Game Tick 的确定性不受客户端帧率影响。
- 多视口客户端可以只订阅需要显示的世界。
- 服务端和渲染端可以独立部署、调优和崩溃恢复。
- 需要额外处理快照带宽、插值误差和跨进程生命周期。
